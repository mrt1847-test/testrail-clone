# 사용자 가이드 작성 중 발견한 후속 작업

작성일: 2026-09-24. 추가 작업은 미착수다. 실행 순서는 이 로컬 프로젝트의 [NEXT_ACTIONS](./NEXT_ACTIONS.md)가 소유한다.

## 관찰 기준과 적용 원칙

[한국어 사용자 가이드](./user-guide/README.md)를 작성하면서 `cea2fd676156969d2442b5eef3e7c9026465cf7b` 기준 로컬 메모리 저장소에서 관찰한 내용이다. 가상 프로젝트 `온라인 상점 QA`와 테스트 계정을 사용했다. 현재 통합 코드에서 재현한 결함 목록이나 원인 분석 결과는 아니다.

로컬 NEXT_ACTIONS의 2026-09-24 기록은 Current UI-021, UI-065~072 완료 및 작성·실행 통합 재검증 pass다. 남은 UI-021 대기는 E01 실제 첨부 저장소와 E03 독립 테스터 관찰이다. 이는 기존 문서 기록이며 이번 문서 작업에서 제품을 재검증한 결과가 아니다.

**Steps 저장 화면 문제와 재시도 중복은 이미 완료로 기록된 UI-067·068 범위다.** 옛 촬영 환경의 관찰로 완료 작업을 다시 편성하지 않는다. UG-01은 과거 관찰의 연결 기록으로만 남긴다. 현재 로컬 코드에서 회귀가 확인될 때만 별도 수정으로 편성한다. 추가 검토 대상은 UG-02~06이며, 환경 제약과 미검증을 확정 결함으로 취급하지 않는다.

## UG-01 — 기존 UI-067·068에 연결하는 관찰

- 관찰: Steps 저장 후 편집 화면에 이전 값이 남았고 새로고침하면 저장 내용이 보였다. 재시도 과정에서 단계 중복도 관찰했다. 두 현상의 공통 원인이나 특정 요청의 중복 여부는 아직 확정하지 않았다.
- 근거: [3장 저장·복구 안내](./user-guide/03-case-authoring.md). 당시 네트워크 추적은 없으므로 이를 확정 원인 증거로 사용하지 않는다.
- 소유: UI-067의 저장 후 화면 일치와 UI-068의 성공 step ID 보존·실패 작업만 재시도 기준으로 처리한다. 해당 작업의 기존 증거와 현재 코드를 확인하고 같은 fixture의 요청·응답·재조회로 관찰을 검증한다. 별도 수정 큐나 UI ID를 만들지 않는다.
- 완료 기준: 저장 직후 재로딩 없이 읽기·편집 화면이 저장값과 일치한다. 빠른 반복 저장, 실패 후 재시도, 재열기·새로고침에서 의도하지 않은 단계 중복이 없다. 실패 시 초안과 오류가 유지되며 저장 성공을 오인하지 않는다. Text 템플릿과 취소 무변경도 확인한다.
- 제외: 전체 케이스 편집기 재설계. 이미 해결된 경우 같은 조건의 재현·회귀 증거로 종결한다.

## UG-02 — Run 토론 댓글

- 관찰: 메모리 환경에서 Post comment가 `execution comments require prisma mode` 오류로 실패했다. 결과 입력의 Comment는 저장됐다. 두 경로를 구분해야 한다.
- 근거: [8장 협업](./user-guide/08-collaboration.md), [실제 오류 화면](./user-guide/images/08-discussion.jpg).
- 작업: 메모리 모드의 의도된 지원 범위를 확인한다. 미지원 계약이면 제출 전에 제한과 사용 가능한 환경을 안내하고 실패해도 입력을 보존한다. Prisma 환경에서 토론 댓글 저장·재조회·권한 처리를 확인한다. 메모리 저장 구현 추가는 별도 범위 결정 후 진행한다.
- 완료 기준: 미지원 환경에서 지원되는 기능처럼 오인하지 않으며 원시 서버 오류만으로 끝나지 않는다. 지원 환경에서는 새로고침 후 같은 댓글이 보이고 실패 후 재시도로 중복이 생기지 않는다. 결과 Comment 경로는 회귀 없이 유지된다.

## UG-03 — CSV 가져오기

- 관찰: Source와 Map columns를 거친 뒤 Dry run에서 `feature requires prisma mode` 오류가 발생했다. 가져오기 성공은 확인하지 못했다.
- 근거: [9장 데이터 입출력](./user-guide/09-data-exchange.md), [검증 오류 화면](./user-guide/images/09-validation.jpg).
- 작업: UG-02와 공통 환경 안내를 재사용할 수 있는지 확인한다. 기존 Prisma 테스트 환경에서 정상 행·잘못된 행·매핑 수정·재검증·Import를 수행하고 저장된 케이스를 재조회한다. 원자적 가져오기 실패와 재시도의 실제 동작도 확인한다.
- 완료 기준: 미지원 환경은 입력 전에 제한을 알 수 있다. 지원 환경에서 검증 결과와 생성 건수·필드가 일치하고 잘못된 데이터는 계약대로 거부된다. 실패 후 수정·재시도에서 예기치 않은 부분 생성이나 중복이 없다. 성공 화면과 복구 절차를 9장에 반영한다.
- 재개 조건: 기존 Prisma 테스트 DB와 테스트 계정 확보. 사용자 DB 초기화나 새 외부 인프라 생성은 이 작업 범위가 아니다.

## UG-04 — Activity 기록

- 관찰: 예제 결과를 저장한 후에도 메모리 환경의 Activity는 `No activity yet`였다. 메모리 모드 제한, 기록 대상 이벤트, 조회 조건 중 무엇이 원인인지는 미확정이다.
- 근거: [8장 활동 안내](./user-guide/08-collaboration.md), [Activity 화면](./user-guide/images/08-activity.jpg).
- 작업: 결과 저장이 Activity 기록 대상인지 명세·구현을 확인한다. 같은 프로젝트에서 이벤트 생성과 조회를 메모리/Prisma로 비교한다. 계약 위반이면 기록 또는 조회를 수정하고, 의도된 제한이면 화면·문서에 안내한다.
- 완료 기준: 지원 대상 이벤트가 올바른 프로젝트·행위자·시각으로 나타나며 새로고침 후에도 계약대로 조회된다. 미지원/빈 상태와 조회 실패를 구분한다. 결과가 저장됐다는 이유만으로 모든 이벤트가 표시되어야 한다고 가정하지 않는다.

## UG-05 — UI가 없는 관리 기능

- 관찰: Plan Configuration 그룹 생성 UI, 사용자 그룹 생성 UI, 별도 요구사항 CRUD 화면을 찾을 수 없었다. 사용자 그룹 화면은 API 사용을 안내했다. 케이스 References 입력은 요구사항 엔터티 생성과 다르다.
- 근거: [6장 Plan](./user-guide/06-plans-milestones.md), [8장 요구사항](./user-guide/08-collaboration.md), [10장 관리](./user-guide/10-administration.md).
- 작업: 세 기능 각각을 기존 제품 명세·FEATURE_CHECKLIST와 대조해 UI 구현 예정/API 전용/범위 밖 중 하나로 결정한다. API 전용이면 필요한 역할·사전 설정·시작 경로를 문서화한다. UI 구현이 필요하면 각각 별도의 범위·권한·완료 기준을 가진 작업으로 편성한다.
- 완료 기준: 세 기능의 지원 상태와 사용자 경로가 명세·화면 안내·가이드에서 일치한다. UI 추가가 승인된 항목만 구현 큐에 들어간다. 이 조사 완료를 세 UI 구현 완료로 표시하지 않는다.

## UG-06 — CI·외부 결함 연동 미검증 해소

- 관찰: 설정·업로드 화면만 확인했다. 토큰 발급, 실제 CI 결과 업로드, 외부 서비스 연결은 수행하지 않았다. 실패가 확인된 항목은 아니다.
- 근거: [9장 자동화](./user-guide/09-data-exchange.md), [10장 토큰·연동](./user-guide/10-administration.md).
- 작업: 기존 허용된 테스트 환경과 계정·권한을 확인한 뒤 CI 매핑·업로드·실패 행 재시도와 결함 제공자 연결·생성/조회 흐름을 각각 검증한다. Retry failed items가 CI를 다시 실행하는 기능인지, Retest 대기열 작업인지 혼동하지 않도록 실제 계약을 확인한다.
- 완료 기준: 업로드한 결과가 올바른 케이스·Run에 연결되고 실패 행과 재시도 결과를 추적할 수 있다. 외부 결함 키·링크·조회가 대상 테스트와 일치한다. simulated 결과를 실제 연결 성공으로 기록하지 않는다. 비밀값 없는 증거를 가이드에 반영한다.
- 재개 조건: 테스트용 연동 대상·권한과 필요한 자격 증명이 준비되어야 한다. 준비되지 않으면 필요한 조건만 기록하며 다른 작업은 계속한다.

## 공통 완료 처리

- [ ] 현재 로컬 코드와 기존 완료 작업의 중복 확인, 재현 환경·기대/실제·원인 기록.
- [ ] 수정한 동작에 필요한 회귀, 관련 lint/build, 실제 화면 조작 및 저장 후 재조회 확인.
- [ ] 영향받는 사용자 가이드의 설명·이미지·환경 제한 갱신.
- [ ] 각 UG 항목의 완료/제약과 연결된 실행 단위를 기록하고 NEXT_ACTIONS에서 다음 작업 갱신.

이 문서는 후속 작업 정의다. 제품 수정·검증 완료나 기존 UI 큐의 완료를 뜻하지 않는다.
