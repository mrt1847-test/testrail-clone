# 테스트케이스 생성·편집 흐름 검토와 후속 작업

## 목적과 판정 범위

테스터가 제목을 빠르게 수집하고, 수행 가능한 지침을 작성하며, 저장된 내용을 믿고 다시 읽거나 수정할 수 있는 흐름을 만든다. 목록 quick outline과 옆 패널 편집은 유지한다. 전체 작성 폼과 동일한 저장·초안 보호 계약을 적용하며 새 편집기·카드·메뉴를 추가하는 방식으로 해결하지 않는다.

검토 기준: `cea2fd6`(title-only list add, side QPane, in-panel edit) 및 직전 커밋 비교. 2026-09-20 검토에서 사용자 DB와 분리한 API `localhost:4100` in-memory / web `localhost:5175`를 사용했다. 아래는 **검토 당시 관찰이며 수정 완료 증거가 아니다**. UI-065~072는 이후 로컬에서 완료됐다. 이 문서는 과거 원인 근거로만 보존한다. 현재 계약은 [활성 계획](../superpowers/plans/2026-09-23-testrail-page-ux.md), 실행 순서는 [NEXT_ACTIONS](../NEXT_ACTIONS.md)에서 확인한다.

### 유지할 동작

- 섹션 안 quick outline은 제목 입력 후 Enter로 생성하고 다음 제목 입력에 초점을 유지했다.
- 생성한 케이스를 옆 패널에서 읽고 Edit로 보완할 수 있다. 이를 모달 중첩이나 별도 관리 화면으로 되돌리지 않는다.
- Text/Steps 템플릿별 지침과 References 등 기존 필드 의미를 보존한다.

### TestRail 참고와 적용 결정

[공식 Adding test cases](https://support.testrail.com/hc/en-us/articles/14438119644692-Adding-test-cases)는 전체 Add Test Case 폼과 섹션 하단의 제목 전용 quick outline을 별도로 제공하며 생성·편집 단계의 첨부를 설명한다. 이 프로젝트에서는 상단 **Add Test Case = 전체 작성**, 섹션 끝 **Add Case = 빠른 제목 추가**로 구분한다. 참고 제품의 모든 기능이나 화면 장식을 복제하지 않는다.

## 통합 작성 계약

1. 생성: 섹션/템플릿 문맥 확인 → 제목·실제 지침 작성 → 저장 → 해당 케이스 읽기. Add & Next는 성공 후 같은 섹션에서 다음 작성으로 이동한다. 저장 일부 실패는 다음으로 이동하지 않는다.
2. 빠른 수집: 섹션에서 제목 연속 추가 → 케이스 선택 → 패널 Edit로 지침 보완. 제목만 있는 케이스를 수행 가능한 케이스와 혼동시키지 않는다.
3. 편집: 하나의 본문+Steps 저장 작업으로 처리한다. 모든 단계 완료 후 상세/목록/버전을 갱신하고 저장 사실을 표시한다. API 성공만으로 화면 반영을 대체하지 않는다.
4. 이탈: Section 변경은 입력 보존. 실제로 초안을 버리는 Close/Cancel/다른 대상·경로 이동은 공통 보호. 이미 저장된 케이스나 첨부를 Cancel이 취소한다고 오해시키지 않는다.
5. 실패: 본문 미저장과 본문 저장/Steps·첨부 일부 실패를 구분한다. 성공한 ID와 실패 초안을 유지하고 실패한 작업만 재시도한다.
6. 복귀: 저장·취소 후 기존 suite/section/검색/범위/필터/보기 문맥을 복원한다. 필터에 새 케이스가 맞지 않으면 필터를 몰래 제거하지 않고 저장된 케이스로 가는 조용한 링크를 제공한다.

## 검증과 실행 경계

- 관련 기존 단위 테스트 14개가 통과했지만 CA-F01–03 실제 결함을 검출하지 못했다. 기존 성공을 새 작업 완료 근거로 사용하지 않는다.
- 각 단위는 자신의 실패 회귀 → 최소 수정 → 관련 자동 검사 → 실제 UI/실키 → 저장 후 재조회 순으로 완료한다. 상세 범위·파일·수용 기준은 UI-065–072에 있다.
- 기본 화면 크기 1280×720, 390×844. 배치 변경 UI-069/070/071은 1440×1000도 확인한다. 같은 데이터·상태·배율의 전후 캡처와 결과를 `docs/ux-evidence/UI-XXX.md`에 남긴다. 아직 존재하지 않는 증거 문서를 완료 근거로 연결하지 않는다.
- `npm.cmd run lint -w apps/web`, `npm.cmd run build -w apps/web` 및 변경한 흐름의 회귀 테스트를 실행한다. UI/요청 순서 회귀가 필요하며 직렬화/helper 테스트만으로 대체하지 않는다.
- 역할별 읽기 전용, 긴 지침·필수 custom 필드, 저장 중 이탈/중복 제출, 느린 응답·부분 실패, 필터 밖 생성 케이스를 각 소유 단위에서 확인한다.
- UI-071은 파일 staging/소유권/기존 업로드 연결과 복구 UI를 담당한다. 실제 저장소 원본 bytes 왕복·독립 테스터 수용은 UI-021/E01/E03에서 별도로 판정한다. mock은 실제 bytes 성공이 아니며 새 인프라·계정·유료 서비스 생성은 허용하지 않는다.
- 이번 변경은 문서 편성뿐이다. 제품 코드 수정, 완료 체크, 자동화 변경은 하지 않는다.
