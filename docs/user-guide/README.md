# 한국어 사용자 가이드

온라인 상점의 로그인 기능을 준비하고 검증하는 하나의 여정으로 QA Rail을 익힙니다. UI의 영어 버튼 이름은 그대로 표기합니다.

## 목차와 작성 범위

| 순서 | 영역 | 작업과 화면 확인 범위 |
| --- | --- | --- |
| 1 | [시작하기·탐색](01-getting-started.md) | 로그인, 프로젝트 선택, 공통 탐색 |
| 2 | [케이스 관리](02-case-organization.md) | Suite/Section/하위 섹션, 범위·필터·검색 |
| 3 | [케이스 작성·편집](03-case-authoring.md) | 상세, Text/Steps, 첨부, 저장·취소 |
| 4 | [Run 준비](04-run-planning.md) | 전체·선택·동적 구성, 담당자, 일정 |
| 5 | [테스트 수행](05-execution.md) | 결과, 다음 테스트, 일괄 처리, 재시도, 종료 |
| 6 | [Plan·Milestone](06-plans-milestones.md) | Entry, Configuration, 일정별 진행 관리 |
| 7 | [현황·보고서](07-reports.md) | Overview, 통계에서 원본 결과로 이동 |
| 8 | [협업·추적](08-collaboration.md) | 댓글, 결함, 요구사항, 활동, 알림 |
| 9 | [데이터 입출력](09-data-exchange.md) | 가져오기·내보내기, 자동화, 매핑과 복구 |
| 10 | [관리와 설정](10-administration.md) | 프로젝트·관리자, 권한, 템플릿·필드, 토큰·연동 |

작성 순서: 현재 UI 지원 범위 확인 → 1~5 예제 여정 촬영·작성 → 6~10 화면 확인·작성 → 링크와 이미지 검수. 지원 화면과 실행 환경 제한은 각 영역에 구분합니다.

## 확인 수준과 환경 제한

| 범위 | 확인한 내용 | 제한 |
| --- | --- | --- |
| 1~5 기본 여정 | 프로젝트·섹션·케이스·Run 생성, 결과 저장과 다음 테스트 이동 | Steps 저장 직후 표시 문제는 3장 복구 절차 참고. 재실행·종료는 확인 창까지만 촬영 |
| 6~7 계획·보고 | Plan Entry와 Run 생성, Milestone·보고서 화면 | Configuration 그룹 생성 UI는 없으며 사전 구성이 필요 |
| 8 협업 | 결과 Comment·Defects 기록, 토론·활동·알림 화면 | 실행 토론 댓글은 메모리 저장소에서 실패. 요구사항 관리 전용 UI 없음 |
| 9 입출력 | CSV 매핑과 검증 오류, 내보내기·자동화 화면 | Prisma가 필요한 가져오기 성공과 실제 CI 업로드는 미검증 |
| 10 관리 | 권한·템플릿·필드·토큰·연동 설정 화면 | 실제 권한 변경, 토큰 발급, 외부 서비스 연결은 수행하지 않음 |

## 화면 기준

- 코드: `cea2fd676156969d2442b5eef3e7c9026465cf7b`의 별도 checkout. 제품 코드는 수정하지 않습니다.
- 촬영: 2026-09-24, 로컬 메모리 저장소, 가상 계정 `guide@example.com`. 서버를 재시작하면 예제 데이터가 사라집니다.
- 다른 작업의 미커밋 UI 변경은 포함하지 않습니다. 기존 UI 개선 큐의 Current는 UI-066이며 이 가이드로 완료 처리하지 않습니다.
- 작성·취소·본문/Steps·첨부·목록 문맥 및 Cases/Run 페이지는 개선 예정 영역입니다. 이 기준 화면 설명으로 읽고, 해당 UI 변경이 통합된 후 관련 이미지를 재촬영해야 합니다.

재촬영 대상은 Cases 변경 시 2~3장, Run 생성·수행 변경 시 4~5장, 공통 탐색 변경 시 각 장의 전체 화면입니다. 저장소를 Prisma로 전환하면 8장의 토론과 9장의 가져오기 성공 흐름도 다시 확인합니다.
