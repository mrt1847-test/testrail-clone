# Roadmap

Updated: 2026-09-23. 제품 방향만 관리한다. 상세 기능 상태는 [FEATURE_CHECKLIST](./FEATURE_CHECKLIST.md), 실제 실행 순서는 [NEXT_ACTIONS](./NEXT_ACTIONS.md)다.

## 현재 방향

TestRail의 공식 문서와 화면을 기준으로 테스터의 케이스 탐색→작성→읽기→Run 수행→결과 기록→재개 흐름을 완성한다. 기능이 존재하는지보다 페이지 전체의 정보 위계·공간 배분·행동 의미·일관성을 먼저 개선한다. 화면의 외형만 복제하거나 개별 기능 수를 늘리지 않는다.

## 우선순위

1. 초안 보호, 본문/Steps 저장 일치, 부분 성공 재시도와 복귀 문맥을 안정화한다.
2. Cases 전체 계층/범위와 작성·읽기 공간을 정리한다.
3. Run 요약/목록/상세/일괄 대상, 결과창의 정상/실패 상태를 하나의 업무 흐름으로 정리한다.
4. Plan·Overview·Milestone는 공식 동일 상태의 전체 화면 근거를 확보한 뒤 필요한 수정만 편성한다.
5. 전체 여정과 실제 첨부 bytes·키보드·독립 사용자 수용을 통합 검증한다.

구현 단위와 체크는 [활성 실행 계획](./superpowers/plans/2026-09-23-testrail-page-ux.md)에만 둔다. 기능 체크가 완료여도 페이지 사용성 합격을 뜻하지 않는다.

## 이후 범위

기존 보고/추적성·협업/연동·호환성 기능은 보존한다. 추가 기능은 core 흐름이 안정된 뒤 실제 요구와 FEATURE_CHECKLIST의 미완료 상태로 우선순위를 정한다. SSO/MFA·고급 승인·데이터셋·cross-project reports와 별도 자동화 생성기 프로젝트는 현재 실행 큐 밖이다. 과거 wave나 날짜별 검토의 지시를 새 구현 큐로 사용하지 않는다.

## 변경 원칙

제품 요구는 PRODUCT_SPEC, API/DB/도메인 계약은 해당 스펙, 실행 순서는 NEXT_ACTIONS가 각각 소유한다. 현재 코드와 검증 없이 완료 상태를 올리지 않는다. 새 계획·감사 문서를 누적하는 대신 소유 문서를 갱신한다.
