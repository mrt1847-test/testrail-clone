# UI/UX 재점검 — 단순한 화면과 예측 가능한 동작

점검일: 2026-09-18

이번 변경은 **점검과 작업 정의만** 수행한다. 제품 코드 구현, 완료 체크, Current batch 이동은 포함하지 않는다. 실행 체크박스의 원본은 [사용성 개선 문서](./USABILITY_REALIGNMENT_2026-09-18.md)의 UI-022~UI-029다.

## 1. 점검 범위와 근거의 한계

- 현재 코드의 조회 범위, 섹션 그룹 렌더링, 메뉴, 선택 작업, 상세 패널, 대화상자를 읽었다.
- 브라우저에서 현재 프로젝트 목록을 확인했다. 프로젝트가 0개여서 기존 케이스/실행 화면을 새로 조작할 수 없었다. 점검용 프로젝트나 TC를 생성하지 않았다.
- 케이스 화면은 기존 UI-003/UI-007 캡처와 현재 코드를 함께 검토했다. 기존 캡처는 당시 화면의 증거이며 이번 실행에서 다시 재현했다는 의미가 아니다.
- TestRail 공식 문서에서 섹션/하위 섹션 구성 및 목록의 개별·전체 접기/펼치기를 확인했다. 아래 조회 범위 3종의 정확한 명칭·기본값까지 TestRail과 같다고 확인한 것은 아니다. 이 부분은 사용자 요구에 맞춘 제품 설계안이다.
- Run Execution의 기존 UX 문제는 원본 백로그에 유지한다. 이번에는 데이터가 있는 실행 화면을 재검증했다고 주장하지 않는다.

### 이전 완료 판단에 대한 정정

UI-007의 테두리 제거와 폴더 트리 방향은 유지한다. 다만 기존 증거에는 모달 겹침이 보이며, 역할/이름 존재 확인만으로 키보드 접근성이 완료됐다고 볼 수 없다. 이전 완료 기록은 당시 범위의 이력으로 보존하고, 이 잔여 결함은 UI-025/UI-026을 완료하기 전까지 해결된 것으로 간주하지 않는다.

## 3. 요청한 섹션별 TC 블록 설계

블록은 각각을 테두리 카드로 감싸는 방식이 아니다. **섹션 경로 헤더 + TC 행 + 다음 그룹과의 여백/얇은 구분선**으로 구성한다. 중첩된 카드, 그림자, 반복 버튼 줄을 만들지 않는다.

- 기본 묶음 기준은 `섹션별`이다. 각 TC는 실제 소속 섹션의 블록에 한 번만 나온다.
- 헤더에는 섹션 경로, 해당 블록에 직접 속한 표시 TC 수, 접기 화살표만 둔다. 예: `인증 / 로그인 · 3개`.
- 상위 블록에 하위 TC를 복제하지 않는다. 상위 섹션의 직접 TC와 하위 섹션의 TC를 별도 블록으로 구분한다.
- 트리와 같은 깊이 우선 순서를 사용한다. 좁은 화면에서 깊이만큼 계속 들여쓰기하지 않고 경로를 줄바꿈해 제목 폭을 보존한다.
- 접기는 표시만 바꾼다. 필터, 조회 범위, 소속, 선택 대상을 몰래 바꾸지 않는다. 접힌 블록에 선택이 남으면 헤더에 선택 수를 알려준다.
- 전체 접기/펼치기는 목록 View 메뉴에 둔다. 매 블록마다 같은 버튼 세트를 반복하지 않는다.
- 직접 TC가 없는 상위 섹션은 필요한 경로 헤더로만 남긴다. 검색 결과가 없는 섹션마다 큰 빈 카드나 Add 버튼을 반복하지 않는다.
- 생성 대상은 선택된 섹션의 전체 경로로 확인 가능해야 한다. 하위까지 조회하고 있다는 이유로 생성 대상이 임의로 바뀌면 안 된다.

## 4. 조회 범위 옵션 — 표시 모드와 분리

| 표시 이름 | 포함 대상 | 섹션 클릭 시 의미 |
| --- | --- | --- |
| 선택한 섹션만 | 선택한 섹션에 직접 속한 TC | 클릭한 섹션으로 조회 범위를 변경 |
| 하위 섹션 포함 | 선택한 섹션 + 모든 깊이의 하위 섹션 TC | 클릭한 섹션을 범위의 루트로 변경 |
| 전체 섹션 | 현재 스위트의 모든 TC | 해당 블록으로 이동. 전체 조회라는 상태는 유지 |

기본값 제안은 `하위 섹션 포함` + `섹션별 묶음`이다. 세 번째 전체 보기는 기존 전체 스위트 탐색을 명시적으로 보존하기 위한 옵션이다. 위 세 가지가 TestRail 현재 UI의 정확한 옵션명이라는 주장은 하지 않는다.

목록 문맥 줄에 `인증 · 하위 섹션 포함 ▾ · 6개`처럼 현재 범위를 짧게 표시한다. 작은 범위 메뉴 하나에서 바꾸게 하며, 세 개의 큰 버튼이나 별도 설정 패널을 항상 펼쳐두지 않는다. View에는 묶음 기준과 행 간격 등 표시 설정을 둔다. 행 간격을 바꿔도 조회되는 TC 집합은 달라지지 않아야 한다.

URL에는 선택 섹션·범위·필터가 일관되게 반영되어 새로고침/뒤로 가기/링크 공유에서 재현되어야 한다. 사용자별 마지막 보기와 저장된 보기에도 범위를 포함하되 명시적인 URL을 우선한다. 기존 display URL과 저장된 보기에 대한 호환/변환 규칙을 구현 전에 정의한다.

범위를 바꾸면 숨겨진 TC 선택을 해제하고 그 사실을 짧게 알린다. 범위 밖 상세가 그대로 남지 않게 닫거나 명확히 안내한다. 조회 범위와 무관한 형제 섹션이 섞이지 않도록 프런트와 서버를 함께 검증한다.

### 검증용 시나리오

실제 구현 시 다음 고정 데이터로 검증한다. 이번 점검에서는 생성하지 않았다.

| 섹션 | 직접 TC 수 |
| --- | ---: |
| 인증 | 2 |
| 인증 / 로그인 | 3 |
| 인증 / 로그인 / MFA | 1 |
| 결제 | 4 |

인증 선택 시 `선택한 섹션만`은 2개/1블록, `하위 섹션 포함`은 6개/3블록, `전체 섹션`은 10개/4블록이어야 한다. 로그인 선택 시 직접 범위는 3개, 하위 포함은 4개다. 검색·필터 결과에서도 경로와 블록별 수/전체 수가 일치해야 한다. 같은 이름의 섹션, 직접 TC가 없는 부모, 3단계 이상 중첩, 긴 이름, 390px 화면을 포함한다.

## 5. 실행 단위와 우선순위

원본 체크리스트의 UI-022~UI-029는 모두 미완료로 추가한다. 이 문서는 구현 승인이나 예약 순서 변경이 아니다. NEXT_ACTIONS의 Current batch와 기존 다음 후보는 그대로 둔다.

권장 검토 순서는 UI-025(가려지는 대화상자) → UI-022(정확한 범위) → UI-023(블록 소속) → UI-024(설정 단순화) → UI-026/027/028/029다. 실제 일정 편성은 별도로 결정한다.

각 구현 완료 시 스크린샷만 확인하지 말고, 사용자가 현재 위치·대상·다음 행동을 설명할 수 있는지 검증한다. 메뉴 안으로 모든 버튼을 옮겨 메뉴가 복잡해지는 방식도 통과시키지 않는다.
