# TestRail형 화면 구조 재검토와 후속 작업

작성일: 2026-09-19. 상태: 검토·설계·작업 큐 갱신만 수행. 제품 UI 구현 또는 신규 브라우저 검증 완료를 뜻하지 않는다.

이 문서는 작성 당시의 진단·설계 근거다. 아래 ‘현재/미완료’는 그 검토 시점을 가리키며 실시간 상태가 아니다. 이후 통합된 상위 문서의 상태별 노출 규칙·시안 검토·검증 단계가 우선한다. 현재 실행 위치는 NEXT_ACTIONS에서만 읽는다.

후속 작업 내용 검토: 상위 문서 §7의 **Task-content audit against TestRail**에서 기존 48개 항목을 각각 판정하고 UI-038/039/043–048의 목표 화면·동작을 구체화했다. 특히 UI-045의 고정 전체 우선 가정은 공식 Run 선택 의미에 맞게 대체했고, UI-047은 생성 버튼 정리를 넘어 실행 가능한 Run 목록을 우선하도록 재작성했다. UI-049(지침 작성), UI-050(기존 Runs/Plans 실행 허브)을 추가했다. 아래 옛 요약보다 해당 작업 본문과 R1–R7 근거를 따른다.

완료 체크박스는 [상위 UI/UX 문서](./USABILITY_REALIGNMENT_2026-09-18.md), 실행 순서는 [NEXT_ACTIONS](./NEXT_ACTIONS.md)에서만 관리한다.

## 1. 결론: 무엇을 수정했고, 왜 여전히 복잡한가

기존 작업은 무의미했던 것이 아니다. 섹션 범위와 블록, 트리 키보드 조작, 선택 작업줄, 상세 헤더, 결과 복구 등은 각각 개선되었다. 그러나 **일부분의 버튼 정리와 기능 검증을 전체 화면의 사용성 완료로 확대해석했다.** 다음 문제가 남아 있다.

- UI-027은 Cases 위쪽 공간을 줄였지만 전역 조작 → 프로젝트명 → 여러 탭 → 페이지 제목 → 도구줄의 누적 구조 자체는 남았다.
- UI-029는 상세 **헤더**를 정리했다. 상세 **본문**에는 여전히 Quick edit metadata 폼이 Steps보다 먼저 나오고 하단 Edit/복사/삭제 명령이 반복된다. 헤더 완료가 읽기 화면의 완료는 아니다.
- UI-033은 Run 행의 제목·Status 가독성을 개선했다. 그러나 통계 / 트리 / 목록 / 상세의 네 열과 상세 안의 입력 폼이라는 구조는 바꾸지 않았다.
- UI-034는 Run별 테스트 식별을, UI-036은 빈 Plan의 설정 노출을 개선했다. 필터 상시 노출과 여러 생성 명령의 경쟁은 별개로 남았다.
- 공통 컴포넌트가 있어도 카드형 헤더·테두리·그림자·개별 폼이 기본값이면 복잡한 모양을 공통으로 재생산한다. 재사용 여부만으로 완료 판정할 수 없다.
- 이전 UI-037–040은 요청에 따라 설계만 작성하고 실행 후보에 넣지 않았다. 따라서 공통 결과창·읽기 중심 패널·상단 통계는 실제 개선도, 다음 실행 대상도 아니었다. 이번 작업 추가 요청으로 큐에 명시적으로 포함한다.

목표는 기능을 없애거나 TestRail의 옛 색상·로고를 복제하는 것이 아니다. **케이스를 찾고 읽고 관리하는 흐름, Run에서 지침을 읽고 테스트한 뒤 결과를 기록하는 흐름을 가장 쉽게 만드는 것**이다.

## 3. 선택한 접근

1. 개별 버튼만 계속 이동: 변경은 작지만 누적된 화면 구조를 해결하지 못한다.
2. 모든 화면을 한 번에 재작성: 시각 통일은 가능하지만 기존 동작·복구·선택 계약을 훼손할 위험과 검증 범위가 크다.
3. **공통 화면 구조를 먼저 정하고, 기존 화면별로 교체:** 채택한다. 아래 구조와 제거 대상을 공유하면서 한 실행에서는 한 단위만 변경한다. 새 프레임워크·디자인 시스템을 별도로 만들지 않는다.

### 공통 화면 규칙

- 한 전역 문맥 줄, 한 프로젝트 탐색 줄, 한 평평한 페이지 제목/주 작업 영역, 실제 콘텐츠 순서다. 프로젝트명을 같은 계층에서 반복하지 않는다. Run/Case처럼 서로 다른 문맥의 이름은 유지한다.
- 바탕은 평평한 읽기 화면이다. 구역은 제목·간격·얇은 구분선으로 구별한다. 카드 안에 카드, 섹션/행마다 둥근 테두리, 상태별 큰 타일을 기본값으로 쓰지 않는다.
- 테두리를 모두 없애지 않는다. 입력창, 팝업 경계, 선택/포커스, 오류/경고처럼 의미 있는 경계는 유지한다. 상태는 색뿐 아니라 텍스트로도 알 수 있어야 한다.
- 각 작업 영역의 기본 상태에는 강조 CTA 하나. 행 탐색은 텍스트/가벼운 조작, 선택 후 일괄 명령은 문맥 작업줄, 드문 관리 명령은 대상이 명확한 메뉴로 구분한다.
- Cases와 Run은 동일한 목록/트리/상세 문법을 사용하되 역할은 다르다. Cases는 정의를 관리하고, Run은 해당 테스트 인스턴스의 지침을 읽고 결과를 남긴다. Cases에 전역 실행 Status를 만들지 않는다.
- 섹션은 이미 개선한 텍스트·폴더 아이콘 트리를 유지한다. 섹션별 TC 블록, 현재/하위 포함 범위, 선택 일관성도 보존한다.
- 390px에서는 탭과 모든 필터를 여러 줄로 쌓지 않는다. 현재 위치와 명시적인 탐색/필터 진입점은 보이고, 상세는 목록을 대체하는 읽기 화면과 돌아가기 동작을 제공한다. 필수 수행 지침은 접힌 고급 설정으로 보내지 않는다.
- 자주 쓰는 동작까지 모두 점 세 개에 숨기는 것은 단순화가 아니다. 메뉴 이름과 대상, 적용 중인 필터·선택·범위를 화면에서 알 수 있어야 한다.

### Run의 최종 구조

Run 제목 아래 낮은 상태 통계 → 목록 검색/필터 → 섹션 트리 + 테스트 목록 + 선택한 케이스 지침. 통계용 네 번째 열은 없다. 상세는 사전조건·Steps·Expected를 먼저 읽고 하단에서 Add result / Pass & Next를 실행한다. 목록 Status와 Add result는 동일한 작은 결과창을 연다. 구체적인 데이터·저장·복구 계약은 UI-037–040 설계를 따른다.

## 5. 검증 규칙: 같은 실패를 완료 처리하지 않기

각 UI-041–048은 상위 문서의 자기 범위/완료 조건과 아래 조건 중 해당 범위의 조건을 충족해야 한다. 모든 화면의 최종 결과를 각 단위에 요구하지 않는다. 상위 문서 §5.3과 §8의 시안 검토 및 단위/회귀/통합 검증 구분이 우선한다.

- 구현 전 동일 데이터의 현재 화면을 다시 캡처하고, **무엇을 없애고 어디로 옮겼는지** 짧게 기록한다. 이 문서의 과거 캡처를 새 before로 대체 사용하지 않는다.
- 1440×1000, 1280×720, 390×844에서 초기 viewport와 필요한 선택/상세/편집 상태를 남긴다. 화면 일부를 스크롤한 사진만으로 상단 혼잡이나 전체 위계를 통과시키지 않는다.
- 정상 데이터는 긴 제목, 같은 이름의 하위 섹션, 여러 단계 지침, 두 Run에 속한 동일 케이스를 포함한다. 빈 데이터, 로딩, 오류는 별도로 검증한다.
- 메뉴 이동 후 기존 기능 접근성, 키보드 포커스/복귀, 명확한 이름, 선택·필터·URL 일치를 확인한다. 클릭할 수 없는 장식 컨트롤을 새로 만들지 않는다.
- 최종 목표는 Cases/My Tests의 390px 초기 화면에서 제목·첫 행, Run의 상세를 닫은 초기 화면에서 첫 테스트 행이 보이는 것이다. Cases 탐색은 UI-041, My Tests는 UI-046, Run은 UI-040/039의 해당 변경 범위 및 UI-021에서 판정한다. UI-042에 미래 화면의 필터/상세 재설계를 요구하지 않는다. Run은 1280px에서 트리/상세와 함께 여섯 행의 제목/상태를 읽을 수 있어야 하며, 이를 위해 지침을 숨기거나 글자를 축소하지 않는다.
- UI-042에서는 세 대표 경로의 페이지 외형을 나란히 비교한다. 각 단위에서 관련 회귀 테스트·웹 타입 검사·빌드와 실제 키보드/화면 검증을 수행한다. 개발 서버/fixture가 없으면 차단 사유를 기록하고 완료 체크하지 않는다.
- evidence에는 viewport, fixture, 행동, 결과, 남은 제한, 전후 이미지 경로를 적고 최종 응답에는 핵심 전후 이미지를 첨부한다.
- UI-021은 전체 목표 배치에서 케이스 관리 → Run 생성 → 지침 읽기 → 결과/첨부 → 다음 테스트까지 이어서 확인한다. 컴포넌트 존재나 버튼 수 감소만으로 통과하지 않는다. '5초 안에 이해' 같은 사용자 판단은 실제 관찰 여부를 명시하고 자동 테스트 성공으로 대체하지 않는다.

## 6. 실행 순서와 비범위

정확한 현재 작업과 다음 순서는 NEXT_ACTIONS가 단일 기준이다. 이 문서의 작업 표나 번호가 작은 순서로 자동 실행하지 않는다. UI-021은 전체 UX 목표와 테스터 수용성을 종합 판정하며, 개별 배치에서는 정해진 한 단위만 수행한다.

이번 문서 작성으로 체크박스를 완료로 바꾸지 않는다. 신규 API, 기능 패리티 확대, 차트 라이브러리 교체, 새 디자인 시스템, 전체 화면 동시 재작성은 범위 밖이다. 설계 검토와 후속 작업 추가이며 이번 턴에서 구현을 시작하지 않는다.
